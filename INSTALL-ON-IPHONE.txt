REFALUWASH PWA INTEGRATION — IMPORTANT

This package adds the installable-app foundation to the EXISTING K4.Net website.
It does not create a separate website and it does not change your Supabase content.

FILES TO ADD AT THE REPOSITORY ROOT:
- manifest.webmanifest
- sw.js
- pwa.js
- pwa.css
- assets/refaluwash-icon.svg
- assets/refaluwash-icon-512.png
- assets/apple-touch-icon.png

STEP 1 — Upload these files
1. Open https://github.com/sjmaraX15/K4.Net on your iPhone.
2. Make sure the branch is main.
3. Add the files and folders above at the repository root. The SVG belongs inside an assets folder.
4. Do not replace or delete index.html, blog.html, gallery.html, explore.html, contact.html, admin/, site.css, social.js, or any existing Supabase files.

STEP 2 — Add these lines inside the <head> of EACH PUBLIC PAGE:
(index.html, blog.html, gallery.html, explore.html, contact.html)

<link rel="manifest" href="./manifest.webmanifest">
<meta name="theme-color" content="#083b63">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-title" content="ReFaluwash">
<link rel="apple-touch-icon" href="./assets/apple-touch-icon.png">
<link rel="stylesheet" href="./pwa.css">

STEP 3 — Add this script just before </body> on EACH PUBLIC PAGE:
<script src="./pwa.js" defer></script>

IMPORTANT:
- Do NOT add the public bottom navigation or service-worker script to admin/index.html.
- The existing Admin area stays separate and is deliberately excluded from offline caching.
- Keep all existing scripts and Supabase configuration unchanged.
- Commit the changes to main and allow GitHub Pages to publish.

STEP 4 — Test
1. Open the live site in Safari.
2. Visit Home, Stories, Gallery, Explore, and Contact.
3. Confirm the bottom navigation appears on a phone-sized screen.
4. In Safari, tap Share, then Add to Home Screen.
5. Launch the new ReFaluwash icon from the iPhone Home Screen.

NOTIFICATIONS
This package does NOT turn on email or push notifications yet. Real notifications need:
- a subscriber opt-in form,
- a secure server-side sender (for example, a Supabase Edge Function),
- email-provider credentials stored as server secrets,
- Web Push VAPID keys and stored push subscriptions,
- permission requested only after the visitor taps an Enable Notifications button.

Never put a Supabase service-role key, email-provider secret, or VAPID private key in browser JavaScript or GitHub files. The publishable Supabase key already used by the current site is not a service-role key.

iPhone push notifications require an installed web app and iOS/iPadOS 16.4 or later, plus user permission. Email subscriptions can work independently of push.

ROLLBACK
If anything looks wrong, remove the two PWA tags/links and the pwa.js script from the public HTML pages, then remove the five added files. The original site pages and content remain unchanged.
